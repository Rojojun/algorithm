# 편성 스케줄러 (Broadcast Scheduler)

> CJ ENM 코테 대비 — Day 1
> 유형: 구현 / 시뮬레이션 (조건 많은 상태 관리)
> 제한시간: 50분 (설계 10 / 구현 30 / 검증 10)

## 문제

한 채널의 하루(00:00 ~ 23:59, 총 1440분) 편성을 관리하는 스케줄러를 구현한다.
프로그램 편성 요청이 **시간 순서와 무관하게** 들어오며, 각 요청을 규칙대로 처리한 뒤
**최종 확정 편성표**를 출력해야 한다.

요청은 다음 세 종류다.

### 1) `RESERVE id start dur priority`

콘텐츠 `id`를 `start`분에 시작해 `dur`분간 편성하려는 예약 요청.

- 편성 구간은 `[start, start+dur)` 이다. (start 포함, start+dur 미포함)
- 만약 이 구간이 **이미 확정된 다른 프로그램과 단 1분이라도 겹치면**, 다음 규칙으로 처리한다:
  - 겹치는 기존 프로그램들의 **priority를 전부 확인**한다.
  - 신규 요청의 `priority`가 **겹치는 모든 기존 프로그램보다 크면(높으면)**,
    겹치는 기존 프로그램들을 **전부 취소(제거)** 하고 신규를 확정한다.
  - 그렇지 않으면(하나라도 기존 priority가 신규보다 크거나 같으면) 신규 요청을 **무시**한다.
- 겹치는 게 없으면 그냥 확정한다.

### 2) `CANCEL id`

확정된 편성 중 콘텐츠 `id`를 취소(제거)한다.
해당 id가 편성에 없으면 무시한다.

### 3) `MOVE id newStart`

확정된 프로그램 `id`를 시작 시각만 `newStart`로 옮긴다(러닝타임 dur·priority 유지).
이동 결과 구간 `[newStart, newStart+dur)`가 **다른 확정 프로그램과 겹치면
이동은 실패하고 원위치 그대로 둔다.**
`id`가 편성에 없으면 무시한다.

## 제약 / 정의

- 같은 `id`는 편성표에 **동시에 최대 1개**만 존재한다.
  이미 확정된 `id`로 다시 `RESERVE`가 들어오면(구간 겹침과 무관하게) 그 요청은 **무시**한다.
- 모든 편성 구간은 `0 <= start`, `start + dur <= 1440` 을 만족해야 한다.
  이 범위를 벗어나는 RESERVE / MOVE 요청은 **무시**한다.
- `priority`가 클수록 높은 우선순위다.

## 입력

- 첫 줄: 요청 수 `Q` (1 <= Q <= 100,000)
- 다음 Q줄: 위 세 형식 중 하나
  - `id` (1 <= id <= 1,000,000)
  - `start` / `newStart` (0 <= ... <= 1439)
  - `dur` (1 <= dur <= 1440)
  - `priority` (1 <= priority <= 1,000,000)

## 출력

- 모든 요청 처리 후 남은 확정 편성표를 **시작 시각 오름차순**으로 출력한다.
- 각 줄: `start end id priority` (end = start + dur)
- 편성이 하나도 없으면 `EMPTY` 한 줄 출력.

## 예시 입력

```
6
RESERVE 100 540 60 5
RESERVE 200 560 30 3
RESERVE 300 560 30 9
MOVE 100 540
CANCEL 999
RESERVE 400 700 60 1
```

## 예시 출력

```
560 590 300 9
700 760 400 1
```

## 예시 해설

1. `RESERVE 100 540 60 5`: 겹침 없음 -> 확정 `[540,600)`
2. `RESERVE 200 560 30 3`: `[560,590)`이 100번 `[540,600)`과 겹침.
   신규 priority(3) < 기존(5) -> **무시**
3. `RESERVE 300 560 30 9`: `[560,590)`이 100번과 겹침.
   신규 priority(9) > 기존(5) -> 100번 **취소**, 300번 확정
   (이 시점 편성: 300번 `[560,590)`만 남음)
4. `MOVE 100 540`: 100번은 3단계에서 취소되어 편성에 없음 -> **무시**
5. `CANCEL 999`: 999번 없음 -> **무시**
6. `RESERVE 400 700 60 1`: 겹침 없음 -> 확정 `[700,760)`

최종: 300번 `[560,590)`, 400번 `[700,760)`

## 핵심 함정 체크리스트

- 겹침 판정: `[a,b)`와 `[c,d)`가 겹치는 조건은? (`a < d && c < b`)
- MOVE 실패 판정 시 **자기 자신**과의 겹침은 제외해야 함
- RESERVE 하나가 기존 **여러 개**를 취소하는 경우 처리
- 동일 id 재예약 무시
- start/end 범위(0 ~ 1440) 밖 요청 무시
- Q가 10만 -> 입출력은 BufferedReader / StringBuilder 사용
