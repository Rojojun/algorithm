# 503. Next Greater Element II

**난이도:** Medium

## 문제

**원형(circular)** 정수 배열 `nums`가 주어졌을 때, 모든 원소에 대해 **다음 큰 수**를 반환하라.

`nums[i]`의 다음 큰 수란, 배열을 순회 순서대로(끝에 도달하면 처음으로 돌아가서) 진행했을 때
처음으로 만나는 `nums[i]`보다 큰 수를 말한다. 존재하지 않으면 `-1`.

## 예제

### Example 1
```
Input: nums = [1,2,1]
Output: [2,-1,2]
Explanation:
  첫 번째 1의 다음 큰 수는 2.
  2는 자신보다 큰 수가 없으므로 -1.
  두 번째 1은 원형으로 돌아 앞의 2를 만난다.
```

### Example 2
```
Input: nums = [1,2,3,4,3]
Output: [2,3,4,-1,4]
```

## 제약조건 (Constraints)

- `1 <= nums.length <= 10^4`
- `-10^9 <= nums[i] <= 10^9`

## 왜 이 문제인가

**이미 `leetcode/01/Solution.java`에 `O(n^2)` 완탐 풀이가 있다.** 그걸 `O(n)`으로 개선하는 게 목표다.
(참고: 그 폴더 이름은 `01`이지만 실제 문제 번호는 503번이다.)

BOJ 10828/10845/10866에서 스택·큐·덱을 **구현**해봤으니,
이번엔 그걸 **알고리즘의 도구로 쓰는** 단계로 넘어간다. 키워드는 **모노토닉 스택(monotonic stack)**.

### 접근 순서

1. 기존 `O(n^2)` 풀이를 그대로 두고 새 파일에 `O(n)` 풀이를 쓴다 (BF → 최적화 습관 유지).
2. 스스로 답해본다:
   - 스택에 **값**을 넣어야 하는가, **인덱스**를 넣어야 하는가? 왜인가?
   - 원형 배열을 다루려고 배열을 실제로 두 배 복사할 필요가 있는가?
     인덱스를 `i % n`으로 접근하면 어떻게 되는가?
   - 각 원소가 스택에 최대 몇 번 push/pop 되는가? 그래서 왜 `O(n)`인가?
3. 풀고 나면 **496. Next Greater Element I**을 이어서 풀 것.
   이쪽은 모노토닉 스택 + 해시맵 조합이라 242/560에서 익힌 해시맵이 다시 나온다.
