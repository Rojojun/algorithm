# 560. Subarray Sum Equals K

**난이도:** Medium

## 문제

정수 배열 `nums`와 정수 `k`가 주어졌을 때, 합이 `k`가 되는 **연속 부분 배열(subarray)의 개수**를 반환하라.

부분 배열은 배열 안에서 연속된 원소들의 나열이며, 비어 있지 않다.

## 예제

### Example 1
```
Input: nums = [1,1,1], k = 2
Output: 2
Explanation: [1,1](앞의 둘)과 [1,1](뒤의 둘), 총 2개
```

### Example 2
```
Input: nums = [1,2,3], k = 3
Output: 2
Explanation: [1,2]와 [3], 총 2개
```

## 제약조건 (Constraints)

- `1 <= nums.length <= 2 * 10^4`
- `-1000 <= nums[i] <= 1000`
- `-10^7 <= k <= 10^7`

## 왜 이 문제인가

**이미 잘하는 것(누적합) + 비어 있는 것(해시맵)의 결합.**
BOJ 11659, 11660, 2143에서 누적합은 이미 손에 익었으니, 여기에 해시맵만 얹으면 된다.

### 함정 — 투 포인터로 풀리지 않는다

`nums[i]`에 **음수가 포함**되어 있다. 투 포인터/슬라이딩 윈도우는
"포인터를 옮기면 합이 단조롭게 증가/감소한다"는 성질에 기대는데,
음수가 섞이면 그 단조성이 깨진다. 이게 1번 Two Sum과 같은 종류의 함정이다.

### 접근 순서

1. 먼저 `O(n^2)` 완탐으로 풀어서 정답을 확보한다 (누적합 배열 + 이중 루프).
2. 그 다음 스스로 답해본다:
   `prefix[j] - prefix[i] == k` 를 이항하면 `prefix[i] == prefix[j] - k` 다.
   그러면 각 `j`에 대해 필요한 건 **"지금까지 본 prefix 중 `prefix[j] - k`가 몇 번 나왔는가"** 뿐이다.
   이 조회를 O(1)로 만들려면 무엇이 필요한가?
3. `prefix[0] = 0`을 미리 카운트에 넣어둬야 하는 이유를 설명할 수 있어야 한다.
   (`nums = [3], k = 3` 을 손으로 따라가 볼 것)
